# 从工具闭环测试到编码能力评测

`coding` 子集包含同一计算项目的三档任务。原 `edit-then-run-tests` 保留，继续验证指定工具和编辑后执行测试的闭环。当前数据集为 `agent-eval-v5`：新增任务契约和运行前校准，编码评分改为由父进程比较行为结果；新增任务与协议也改变了统计口径，与 v4 及更早版本不能直接拼接比较分数。

任务质量、隔离执行、重复试验、可靠性测试和版本比较的后续建设见[Agent 自动化评测体系设计](agent-evaluation-system-design.zh-CN.md)。该设计区分当前实现与待建设能力；本页保留三档任务的运行与评分说明。

## 基础任务能证明什么

| 任务 | 分类 / 被测能力 | 通过能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| multi-step-read-edit-verify | 运行机制：读取、编辑、再读 | 指定工具链与修改后缓存刷新可用 | 自主定位 Bug |
| edit-then-run-tests | 运行机制：编辑与执行测试 | 固定补丁和测试闭环可用 | 等价实现是否都被接受、未知 Bug 定位能力 |
| retrieval-citation | 检索能力与引用契约 | 真实召回来源、引用校验链路可用 | 回答完整性、复杂编码能力 |
| long-context-compression | 运行机制：工具结果压缩 | 当前夹具触发压缩且上下文受限 | 压缩提升编码成功率、摘要保留全部约束 |
| prompt-injection-resistance | 模型行为：抵抗注入 | 本样本中未产生指定越权副作用 | 对所有注入安全、摘要语义正确 |
| injection-contained-by-harness | 运行机制：工具边界 | 脚本照做注入时越界写与敏感读取被拒 | 真实模型会主动抵抗注入 |
| cancel-mid-run | 产品流程 / 运行机制：取消 | 注入取消信号后运行正确中断 | 桌面取消按钮交互正确 |
| crash-recovery-run-events | 运行机制：恢复记录 | 注入崩溃后状态及事件记录满足断言 | 所有崩溃位置都能恢复、恢复后任务正确 |
| budget-token-cap、budget-tool-call-cap、iteration-cap-stop | 运行机制：预算停止 | 指定路径的硬上限和停止原因有效 | 预算内能完成任务、成本最优 |
| workflow-preserve-dirty | 产品工作流：保护用户改动 | 夹具里的既有变更被保留 | 任意仓库均无覆盖风险 |
| workflow-steering | 产品工作流：中途指令 | 注入的用户变更进入执行流程 | 所有桌面交互均正确 |
| workflow-stale-verification | 产品工作流：证据更新 | 外部变更后重新生成验证证据 | 验证本身覆盖所有需求 |
| coding-known-location | 编码能力：已知位置修复 | 当前验收覆盖的加法修复与乘法兼容 | 独立定位根因 |
| coding-error-localization | 编码能力：根据报错定位 | 未在提示中指定源码位置时完成同一修复 | 大型仓库搜索能力 |
| coding-cross-file | 编码能力：跨文件接口与回归 | 数量计价、格式接口、空输入和零数量符合验收 | 任意业务需求与所有数值边界均正确 |

以上能力解释针对真实模型模式。离线 scripted model 提供的是工具运行、参考轨迹和评分器接线证据；离线 100% 不能解释为模型编码成功率。

## 运行前质量检查与证据分类

现有 26 题均声明 `evaluation`：轨道 `track`、任务家族 `family`、开发集或保留集 `split`、测量目标 `objective`、结论边界 `limitations` 与人工复核状态 `review`。当前有 24 道开发任务与 2 道保留任务，人工状态均为 `unreviewed`，自动检查不会将它们升级为已独立审核。

每次 runner 启动选定任务前，检查规格和实际可识别的判据类型，并对 coding 任务运行初始版本、参考修复和正反例候选。扩展后的 12 道编码题共 74 个校准候选；任何不符合预期的评分会阻止 Agent 启动，即使提供了真实模型 Key 也不会继续调用。校准报告保存在 `taskQuality`，包含任务契约哈希及 grader 身份；runner 另保存判据实现指纹。独立入口 `eval:quality` 用于检查内置任务规格与编码候选，runner 另核对其检查类型注册表。

JSON 的 `assessment` 和 `trackSummary` 区分机制、编码、流程与可靠性场景，以及 `scripted-regression`、`model-coding-outcome`、`model-contract-outcome` 和 `not-executed`。runner 启动异常标为 `runner-error`；没有完整模型轮次的错误标为 `model-unavailable`。保留的 `totals.successRate` 和重复报告的总体均值是所有判据的兼容诊断统计，不是综合模型能力分。历史报告没有分类时保留 `unclassified`，不根据模型名补猜。

重复报告另按轨道与证据类型汇总，并拒绝混合不同任务或 grader 契约。运行状态、持久证据、重评、容器通道、可靠性任务和统计比较已增加独立入口，详见[运行与验收说明](agent-evaluation-operations.zh-CN.md)；容器工程验收已通过，独立人审仍待完成；真实隔离模型结果与工程 smoke 分开登记。

扩展开发任务还覆盖超时零值、文本归一化、用户搜索、端口解析；保留任务覆盖库存累计与 HTTP 状态判断。改名、需求改写和首次读取故障变体关联原题，同源变体不当作独立家族扩充分数。完整列表可用 `npm run test:eval:list` 查看。

## 三档任务与评分规则

任务、初始代码、公开测试、`reference` 参考文件、`calibration` 校准候选及 `behaviorCases` 行为输入与期望值位于 `scripts/eval/coding-tasks.cjs`。这些参考与验收数据不会作为模型提示发送；三个任务使用各自独立的新工作区。

编码通过仅由 `coding-behavior` 的验收结果决定（看门狗、传输异常等 harness 故障仍判失败）。评分器不要求使用某种编辑工具、固定源码表达式或精确变更文件集合。允许函数改写和在 `src/` 添加辅助文件。跨文件任务通过接口结果验收，不强制实际修改文件数。

`scripts/lib/coding-grader.cjs` 检查初始 `src/` 以外的公开文件字节未变，将候选 `src/` 复制到新的临时目录，然后在子进程加载候选函数。子进程仅接收调用参数，经专用数据通道返回行为结果；期望值和最终比较留在父进程。候选 stdout 中的成功标记及子进程内断言被改写都不能替代结果比较。当前协议支持同步 CJS 函数和有限数字、字符串、布尔期望值，不是任意项目测试框架。

候选测试不参与验收；符号链接、缺失的受保护文件、进程提前退出、行为结果不符和超时均不能通过。加法与乘法共 12 项行为检查，跨文件题另有 6 项购物车与格式接口检查。输入契约见各任务提示。

临时目录用于隔离模块缓存与候选测试，不是操作系统安全沙箱。候选代码仍以本机权限在子进程运行；本轮用于受控学习夹具，不声称能抵御恶意代码攻击评测进程。有限测试也不能证明所有输入正确。

公开测试成功退出且返回预期标记作为 `observations` 写入 JSON 和 Markdown 报告，不影响编码通过率。该信号只便于检查主动验证行为；命令可能被伪造、测试可能早于最终编辑，不应把它解释为终态验证证明。终态以独立验收为准。

## 运行与复核

```bash
# 只检查题目规格与初始、参考、等价及错误候选，不调用模型
npm run eval:quality

# 校验质量门禁与报告分类，包括拦截坏参考修复的 model 模式
npm run test:eval-quality

# 校准评分器：正确的等价实现应被接受，错误补丁与测试篡改应被拒绝
npm run test:coding-grader

# 当前 coding 开发集离线接线；--keep 另保留工作区与兼容轨迹，证据包默认持久保存
npm run test:eval:coding -- --keep --report-dir=/tmp/codenode-coding-eval

# 配置 CODENODE_EVAL_API_KEY 等模型参数后，运行相同子集
node scripts/eval/agent-eval.cjs --subset=coding --mode=model --require-model --keep
```

评分器回归测试现有 34 个场景，覆盖未修复、等价实现（含新增辅助文件）、硬编码公开样例、破坏乘法、改写或删除测试、提前退出、伪造成功标记、篡改子进程断言、符号链接，以及跨文件部分修复；包含真实 runner 的离线接线检查。

读轨迹时先看独立验收的失败断言，再判断是定位失败、实现错误还是回归；结合工具序列、过程观测与 `--keep` 的完整轨迹记录证据。先逐档记录真实模型结果，再增加任务数量和重复次数。三档基础题仍是相关的小型梯度样本，扩展集也不构成综合编码能力排行榜。真实模型对照与可靠性补充诊断的结果见运行说明；尚未进行压缩消融。

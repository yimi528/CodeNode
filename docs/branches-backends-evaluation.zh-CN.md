# 会话方案、后端诊断与项目评测

## 会话与工作区方案

对话栏的“历史方案”入口提供完整流程：

1. 保存编辑器内容，再“保存当前检查点”。Git 临时索引记录当前磁盘中的已暂存、未暂存和未跟踪文件，原暂存区与工作区不变；被 Git 忽略的文件和应用运行目录不进入代码检查点。
2. 从保存的检查点“创建隔离方案”。每个方案建立独立受管 Git worktree，继承该检查点的对话和画布。当前实现要求已具有提交的普通 Git 仓库，并从仓库根目录使用；不能把只有聊天内容的任意旧消息伪装成可执行代码检查点。
3. 切换方案时先持久化当前对话视图，再同步切换项目根、文件树、对话与画布。编辑器未保存或 Agent 正在执行时不能切换。新的模型对话身份不复用源后端的原生会话与审批令牌。
4. 对多个方案分别“比较产物”，并排查看相对检查点的文件统计、补丁与最近对话交付。补丁受输出上限约束，截断会明确标注，源码仍在各自工作树内。
5. 切回主工作区，处理未提交修改后“预览采用”。主进程在 Git 对象中计算相对检查点基线的三方合并；冲突发生时主工作区不变。确认采用时再次核对目标 HEAD、源 HEAD 与未提交文件指纹，过期预览不能执行。只采用方案相对检查点的变化，避免把已有用户草稿误作方案新增修改。
6. 采用后创建包含来源的提交和日志，原会话校验置为失效，必须在目标工作区重新验证。归档保留工作树、补丁检查点与事实记录，不直接删除产物。

检查点与方案使用 `<root>/.codenode/branches/events.jsonl` 追加写入。每项事件包含顺序、前项哈希和当前哈希，读取时校验完整链；投影可从该日志重建。Git 对象通过 `refs/codenode/checkpoints/` 保留。运行元数据与受管工作树不提交到项目源码。

原始模型/工具事件仍保存在各工作区的现有 Run 日志中；会话视图保存到独立方案。代码采用不复制源审批，也不撤销联网、部署等外部副作用。非 Git 快照、任意历史节点重挂和自动合并自然语言对话不在本次功能范围。

## 后端连接与验证程度

Agent 选择器展示命令是否在本机可用，以及当前配置是否检测过连接，并提供“连接诊断与修复”入口。设置面板检测当前命令和参数，展示错误原因、修复步骤和系统隔离快照。检查不会自动安装、登录或保存配置。

协议握手成功只证明当前配置可以握手。历史任务验证必须匹配后端、版本和平台，显示实际覆盖项及缺项；现有 Hermes 记录覆盖连接、只读任务、文件修改和独立检查，不能宣称取消/恢复或权限拒绝已通过。不同命令、参数、模型、权限配置不会继承之前的握手结果。

Windows 文件系统隔离缺口和缺少后端 CLI 等外部限制仍按真实状态报告，不通过降低门禁宣称完成。

## 用真实项目任务比较版本

固定工作流集增加三个任务：保留用户未提交文件、运行中插话改变需求、校验后外部修改并重新验证。旧有崩溃/恢复、取消和预算场景继续保留。数据集版本为 `agent-eval-v2`。

```sh
npm run test:workflow-eval
node scripts/eval/agent-eval.cjs --subset=workflow --mode=model --require-model
```

真实模型使用已有 `CODENODE_EVAL_API_KEY`、`CODENODE_EVAL_BASE_URL`、`CODENODE_EVAL_MODEL` 等设置；缺少凭据以非零退出，不生成假通过结果。运行可能产生供应商费用。

另可通过 `--cases` 使用固定提交的本地真实仓库，运行器创建独立克隆副本，注入配置声明的回归，再执行任务和独立命令验收，原仓库不变。示例使用 CodeNode 的固定提交，对默认任务优先级配置注入并修复回归，无需在副本安装依赖。

```sh
npm run test:project-eval
node scripts/eval/agent-eval.cjs --cases=config/project-eval.example.json --mode=model --require-model
```

案例文件使用 `version: 1` 和 `tasks`。每项指定唯一 id、本地 repository.path、完整 repository.commit、prompt、allowTools、budget 和至少一项 `verify-shell` 独立验收；fixture 可注入回归，editing 可指定该项目局部校验命令。案例原文的内容哈希构成数据集身份，防止改变任务判据后仍与旧报告直接比较。

报告包含成功率、耗时、工具步数、Token、审批请求与人工补充请求计数。离线请求由脚本化模型提供，工具、文件、Git 和独立测试仍实际执行；离线费用及缺少单价的真实模型费用为未知。审批在评测内自动处理，不能把审批请求数当成实际人工操作次数。

```sh
node scripts/eval/agent-eval.cjs --subset=workflow --baseline=/absolute/path/previous-report.json
```

基线比较要求数据集、模式、模型和任务集合一致，输出成功率、耗时、Token 和人工补充请求差值。真实模型能力的提升只能从真实模型报告判断，离线通过仅证明确定性执行链及判据有效。

## 核心边界

`electron/agentPrompt.cjs` 负责身份/规则/画布/记忆等提示文本装配与预算裁剪；`electron/agentOverflow.cjs` 负责供应商超窗识别和进程内窗口观测。Agent 主入口继续导出原接口，保持调用方兼容；模块边界门禁将主循环行数上限下调到 3240，并分别限制新模块规模。提示词段落顺序、正文、工具门控和超窗行为使用原回归集验证。

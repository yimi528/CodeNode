# 任务交付与画布阶段操作

## 对话中的交付卡

一次带有运行、工具、文件变更或校验记录的回答结束后，会展示“本轮交付”；失败、取消或达到限制时展示“本轮阶段性结果”。卡片集中展示变更文件、工具记录中的差异、后端提供的补丁及完整校验结果。文件指纹和未记录差异的文件不会被描述成完整源码 Diff，所选局部校验通过也不代表全部需求验收通过。

“任务验收”单独展示调用方显式配置的产物和命令检查；未配置时显示“需求尚未验收”。显式规则未通过会阻止正常完成，回滚后原证据失效；这类规则通过不会自动授予 Goal 独立验收。配置与终端目录契约见 [终端与显式验收](terminal-and-acceptance.zh-CN.md)。

“查看运行与恢复”打开运行面板，并将事件回放筛选到对应 Run。最新回答可以通过“继续修改”填写并发送下一步要求。

“预览文件回滚”只读取计划。确认后，沿用 Run 的前像回滚机制，仅处理可恢复文件，默认拒绝覆盖后续冲突修改。界面分别报告已回滚、拒绝和跳过的数量及拒绝原因；有文件发生回滚后，该 Run 的旧校验不再显示为当前有效。命令、联网操作和其他外部副作用不会随文件回滚撤销。

## 画布中的阶段操作

Goal 任务节点展示负责人、状态、有效验收数量和已知阻塞原因。点击节点可查看阶段总结、当前会话或已保存会话中关联 Run 的交付卡、全部阶段验收结果以及上游交付；点击上游名称即可切换查看。

- “执行当前阶段”先调用主进程的运行资格检查，然后通过现有聊天执行链绑定 Goal 和 Task，只执行选中阶段；依赖、决定、等待、预算与权限仍由原有机制检查。
- “重新排队此阶段”只更新队列状态，不会立即执行，也不会绕过运行资格检查。
- 未知运行结果必须先人工复核，不能直接执行或重新排队。
- 未处理业务决定可在阶段面板内填写并保存；等待条件、未知结果复核和独立验收通过“处理阻塞与独立验收”定位到原有任务管理控件。
- 已暂停、停止或完成的 Goal 需要先恢复目标，才能重新执行阶段。选中已完成任务后刷新仍保留产物视图，但普通聊天不会因为查看已完成任务而自动绑定到它。

历史运行缺少会话交付记录时，仍可查看阶段总结、验收证据和运行事件，不会补造文件差异。

## 验证入口

- `npm run test:task-delivery`：依赖与决定提示、未知结果优先级、证据有效性、外部变更和回滚状态。
- `npm run test:delivery-ui`：真实 Electron 界面中的文件展示、回滚预览/取消/确认、冲突保护、旧校验失效、继续修改与明暗主题。
- `npm run test:goal-canvas-ui`：任务图、上游导航、完成后保留选择、单阶段执行及未知结果拦截。

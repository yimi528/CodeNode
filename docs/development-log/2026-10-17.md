## 2026-10-17 23:16:19 CST

### 修复的 Bug

- 修复 Windows Job Object helper 占用控制 stdin，导致 ACP、MSP、MCP 等双向 stdio 外部进程只能退回原生启动、失去进程树隔离的问题。
- 修复 `SandboxChild` 的 stdout/stderr 只是事件对象，不能满足 `setEncoding`、`destroy` 等 Node 子进程流接口的问题。
- 修复 broker 同时触发 `error` 与 `close` 时可能重复发出关闭事件的问题。

### 更新内容

- Windows helper 协议升级为逐行 JSON 控制帧，使用 base64 转发任意 stdin 字节，并支持独立的 stdin EOF。
- `SandboxChild` 使用真正的 `PassThrough` 输出流；交互进程获得兼容 Node `ChildProcess` 的 stdin/stdout/stderr 表面。
- `guardedInteractiveSpawn` 在 Windows 上改为进入 Job Object，不再因为双向 stdio 自动跳过进程树与资源隔离。
- Windows 文件系统隔离仍未实现，能力快照继续明确报告 `filesystemIsolation=false`，strict 模式不会误放行。

### 验证结果

- `npm run check:js` 通过。
- `npm run test:sandbox` 通过，覆盖 stdin base64、独立 EOF、stdout 字节还原和 helper 源码接线。
- `npm run test:backends`、`npm run test:multi-backends`、`npm run test:muse-backend`、`npm run test:backend-workflow` 通过。
- `npm run test:mcp-handshake`、`npm run test:mcp-session` 通过，确认双向协议、会话复用、崩溃重启和空闲回收未回归。
- Windows helper 的真实编译和 Job Object 运行需由 Windows CI 完成；当前 macOS 只完成协议与源码接线验证。
